# DESIGN.md — the mobile app language

UI language for the FE for Raccoons mobile app. Read this before building or
changing any screen. Adopted 2026-09-18 (ADR 0016); it supersedes
`docs/mobile/visual-language.md` for the phone.

## How to use this folder

- `reference-screens/png/` shows the target look. Study these first.
- `reference-screens/html/` is the same screens as plain HTML with inline
  styles, generated by `build-screens.mjs` from `tokens.json`. Pull exact
  values (sizes, radii, spacing, colors) from here instead of estimating from
  the images. Regenerate with `node build-screens.mjs && node render.mjs`.
- `tokens.json` holds the design tokens. They are mapped once into
  `lib/core/theme/` and referenced everywhere. Never hardcode a hex or a
  font size in a screen.

**Every reference screen is a feature the app has.** They were rebuilt from an
AI-generated kit whose screens showed sign-in providers, a campus code, a
study-hours gauge, a self-rating deck and a weekly plan. None of those exist
here and none of them are in these references. (`04-exam-date` started as a
proposal; it was built on 2026-09-19, along with `16-mastery` and
`17-days-studied`, the pages behind the three Profile tiles.) Do not build
features because they appear in a reference. Build what the owner asks for,
and make it look and behave like these references.

## The one rule

If a screen looks like a web form, it is wrong. Stop and rethink the
interaction before writing more UI code.

A screen smells like a form when it has: stacked labeled text inputs, a
full-width rectangular submit button at the bottom, thin-bordered white cards
in a single column, hairline-separated list rows as the main content, or small
type everywhere with nothing dominant. `docs/mobile/native-not-form.md` has
the long version and the adjectives to judge by.

## Principles

1. **One job per screen.** Each screen asks one question or offers one main
   action. Split long screens into steps.
2. **Answer with a thumb, not a keyboard.** Prefer tapping, stepping,
   scrubbing, toggling and card decks over typing. A text field appears once
   per screen at most, oversized, with no box.
3. **One dominant element.** Every screen has a single thing far bigger than
   the rest: a giant number, a huge headline, or a large tactile object.
   Hierarchy comes from scale contrast, not from boxes.
4. **Color blocks, not borders.** Separate content with full-bleed color and
   solid filled tiles. No outlines around cards. No drop shadows except under
   the floating dock and a floating decorative card.
5. **Actions live in the thumb zone.** Primary actions sit in the bottom
   third: a 72 round arrow button at bottom right, or a 72 pill spanning the
   width.
6. **Numbers are heroes.** Countdown, lessons to go, days studied: display
   size with a small unit on the baseline.
7. **Every control reacts.** Pressed states scale down slightly, selections
   animate, fills and sizes transition. Nothing changes state instantly.

## Color

The website's hues, moved to the roles an app needs. Derived in OKLCH from the
brand tokens; every pairing below passes WCAG AA.

| Token | Hex | Role |
|---|---|---|
| fog | `#E3DFD7` | The ground. Warm light grey, dark enough that cream tiles read on it |
| charcoal | `#2C2C2C` | Text on every light or accent surface. Dark tiles, dock, avatar, round buttons |
| tile | `#3A3936` | Dark surface: the dock, the mastery row |
| tile2 | `#47453F` | Surface on tile (icon button inside a dark tile) |
| line | `#4F4C45` | The rare divider or dock border on a dark tile |
| cream | `#FFF9F0` | Paper. Sheets, light tiles, answer blocks |
| creamDark | `#F5EDE0` | Second light tile, watermark text on fog |
| spring | `#63F0A8` | THE accent. CTA circle, hero tile, active dock item, the chapter in flight. The brand green (forest) at L 0.86 on the same hue |
| peach | `#FEB89C` | The hot ground: any surface that would have been ember (a tour step, the fluids card). Ember's hue at L 0.84; charcoal on it 8.3:1 |
| ember | `#F0703F` | Warnings, the mastery figure, the answer highlight, strokes. Never a ground (owner's call, 2026-09-18). Web ember two steps brighter so charcoal text passes 4.5:1 |
| butter | `#F9D28A` | The yellow ground: any surface that would have been sunbeam (the days-studied tile, a tour step). Sunbeam's hue at L 0.88; charcoal on it 9.7:1 |
| sunbeam | `#F5B731` | Streak pips, highlights, small marks. Never a ground (owner's call, 2026-09-18) |
| forest | `#2D7A5F` | The brand green as TEXT: field underline and caret, headline accent, done counts. The only green allowed as text on a light ground |
| error | `#D64045` | Errors only |
| mutedOnDark | `#B5ADA3` | Secondary text on charcoal or tile |
| mutedOnLight | `#6B6358` | Secondary text on fog or cream |
| placeholder | `#8C8377` | Input placeholder |
| pipOff | `rgba(44,44,44,0.22)` | Unfilled pip on any light or accent surface |

Rules:

- Text on spring, ember, sunbeam, cream and fog is always charcoal. Never
  cream or white text on spring, ember or sunbeam.
- Text on charcoal and tile is cream, with `mutedOnDark` for secondary.
- A screen uses one ground color edge to edge: fog, spring, peach or butter.
  Charcoal is never a ground (owner's call, 2026-09-18). Consecutive steps in
  a flow change ground color so progress is felt: the sign-up goes fog,
  spring, fog-with-sheet; the tour goes fog, peach, butter.
- Spring, peach and butter are fills. They never appear as thin borders or
  small text on a light ground; ember and sunbeam are never grounds. Spring on cream is 1.4:1: unreadable.
- Two accents per screen at most, counting the ground.
- No gradients. No translucent glass. No hues beyond these.

## Typography

The brand's three faces, with the display face finally allowed to be big.

| Family | Use |
|---|---|
| DM Sans, weights 700 to 800 | Headlines, hero numbers, pill labels, card titles, the oversized field |
| Inter, weights 400 to 600 | Body, supporting text, sheet buttons |
| JetBrains Mono, weights 500 to 700 | Eyebrows, counters, dates, units, any tabular data |

The app bundles DM Sans Bold and SemiBold today (`assets/fonts/`). Add
DM Sans ExtraBold (800) before building any headline or hero number; the
references use it.

| Style | Family | Size / line height | Weight | Tracking | Notes |
|---|---|---|---|---|---|
| hero-number | DM Sans | 118 to 132 / 0.82 | 800 | -0.07em | One per screen at most |
| tile-number | DM Sans | 68 / 0.82 | 800 | -0.06em | Bento tiles |
| headline | DM Sans | 40 to 48 / 0.98 | 800 | -0.045em | The screen's question or title |
| sheet-title | DM Sans | 38 / 1.0 | 800 | -0.045em | Bottom sheets |
| title | DM Sans | 30 / 1.1 | 800 | -0.04em | Greeting |
| pill-label | DM Sans | 22 | 700 | -0.02em | Pill CTAs, answer blocks |
| input-xl | DM Sans | 30 | 600 | -0.03em | The single oversized field |
| body | Inter | 15 to 17 / 1.4 | 400 to 600 | 0 | |
| caption | Inter | 12 to 14 | 500 | 0 | |
| eyebrow | JetBrains Mono | 11 to 13 | 600 | +0.06em | UPPERCASE, the only uppercase |
| data | JetBrains Mono | 12 to 13 | 500 | 0 | Dates, counters |

Headlines are tight: negative tracking, line height near 1.0, wrapped to two
or three lines rather than shrunk. Every big number has a small unit on its
baseline ("73 days", "6 to go").

## Shape and spacing

- Screen side padding 24. Bento screens 16 so tiles run wide.
- Top padding 56 to 58 below the safe area. Bottom 34; on a docked screen the dock carries the inset.
- Radii: tiles and cards 32 to 36, grid tiles 24, bottom sheet top 40, pills
  and round buttons fully round. Nothing under 22 except the 12 pip.
- Gaps: 8 to 10 between tiles, 22 to 30 between major blocks.
- Minimum touch target 44. Primary controls are much larger.

## Components (as drawn in the references)

**Pill CTA.** Height 72, fully round, charcoal fill, cream label in DM Sans
700 at 22, left padding 28. Right end holds a 56 round spring circle with a
charcoal arrow, inset 8. This is the only form the pill takes: every ground
in this app is light, so the pill is always charcoal. (01, 06, 09)

**Round next button.** 72 circle, charcoal, spring arrow at 28. Bottom right.
A low-emphasis text action sits bottom left on the same row. (02, 03, 04)

**Round icon button.** 48 circle, charcoal, cream icon at 20. Back, close,
the Study view toggle. (02 to 06, 09, 10)

**Step indicator.** 8 dots, the current step a 36 by 8 bar, charcoal, the
others at 35 percent. No "1 of 3" text. (02, 05, 06)

**Oversized field.** No box. Transparent, 3 forest underline, DM Sans 600 at
30, forest caret, one caption line under it. One per screen. On a spring
ground the underline and caret are charcoal. (02, 02b, 03)

**Bottom sheet.** Cream, top radius 40, grabber 44 by 5 at 25 percent
charcoal, padding 12 / 24 / 34, over the dimmed previous screen. A sheet
title, one body line, up to three 64 round buttons: the first charcoal, the
rest 2 charcoal outline. (02c)

**Answer blocks.** Cream pills, 76 tall, DM Sans 700 at 24, the letter in a
52 outlined circle at the right. Stack in the thumb zone. (05)

**Card deck.** Cream card, radius 36, padding 26, over a charcoal card at
+5 degrees and a spring card at -3.5. Counter top left, exam weight top
right, the chapter mark centered, title in headline style at the bottom. (06)

**Bento tiles.** Solid fills, no borders. Hero: full width, 252 tall,
spring, an eyebrow, hero number with unit, a 76 round charcoal play button,
a pip row, one caption. Half tiles: 172 tall, cream and sunbeam. Row tile:
96 tall, `tile` fill, big ember value at left, two lines, a 52 round
chevron. (08)

**Chapter tile.** The Study view's one object: cream, radius 36, 470 tall,
eyebrows top, the chapter mark at 108 inside a 176 spring circle, headline
at 40, a mono caption. Pill CTA under it, then the 15 page dots. (09)

**Grid tiles.** 3 columns, cream, radius 24, 116 tall, mark at 28, name in
DM Sans 700 at 11.5 up to 3 lines, mono count. The chapter in flight is a
spring tile; untouched marks are `mutedOnLight`. (10)

**Pips.** Equal capsules 12 tall, gap 4. Filled charcoal, unfilled pipOff.
Under about 20 items prefer pips to a bar.

**Dock.** A full-bleed cream bar with its top corners at 40, under the
content (the scaffold's bottom bar, never an overlay), with a soft upward
shadow. Two labeled destinations, Profile then Study, each a 54 circle over a
12 DM Sans label; the active one a spring circle with a filled charcoal icon.
Light, wide and labeled so it can never be mistaken for the charcoal pill
above it. (08 to 10)

**Chapter marks.** Drawn by the app (`chapter_marks.dart`, designed at 512).
The SVG stand-ins in the references only show placement and size.

**Icons.** Stroke icons, 2 to 2.4, round caps, 20 to 28. Filled only for the
active dock item and the play glyph. No emoji, no multicolor.

## Motion

- Screen content rises in: translate up 18 and fade, 0.5s ease-out, tiles
  staggered by about 60ms.
- Bottom sheet: up 60 with fade, 0.5s, `cubic-bezier(0.2, 0.8, 0.2, 1)`.
- Value changes: 0.25 to 0.45s, slight overshoot allowed.
- Press: scale to 0.95 for 120ms.
- Decorative cards float slowly (6 to 8s loops, a few pixels, about a degree).
- Respect reduce-motion.

## Voice

Short, direct, a little playful. A study partner, not a registration system.

- Questions as headlines: "When's the big day?", "First, your email."
- Buttons say what happens: "Let's go", "Start", "Create my account".
  Avoid "Submit", "Next", "Continue" as labels.
- Honesty rules from the website carry over: mastery is "of the concepts the
  FE tests, not a probability of passing"; never a pass percentage; never a
  countdown to a date the student did not give us ("Set your exam date").
- "Completely free" is the claim; never "free to start".

## Banned

- Stacked labeled inputs, or more than one text field on a screen
- Full-width rectangular buttons, or any button with a radius under 22
- White or cream cards with thin borders; hairline-divided lists as content
- Charcoal as a screen ground
- Gradients, glass, glow, neumorphism
- Emoji, stock illustrations, multicolor icon sets
- Fonts other than the three listed; colors outside the token table
- Center-aligned walls of small text
- Fake status bars or keyboards in mockups

## Accessibility

- Every interactive element is a real button or link with a name.
- Text contrast at least 4.5:1 (3:1 at 24 and above). The pairings in the
  color rules meet this; do not invent new ones.
- Touch targets at least 44.
- Selection never relies on color alone: selected items also change size,
  fill or shape.

## Self-check before calling a screen done

1. Squint: exactly one dominant element?
2. Could the student finish it with one thumb and no keyboard?
3. Is the primary action in the bottom third?
4. Any borders, hairlines, small-radius rectangles, or a charcoal ground?
5. Every color and font from `tokens.json`?
6. Put a screenshot next to the closest file in `reference-screens/png/`. Same app?
